## Как добавить новый репозиторий

1. **Уточнить prod-ветку** у команды:  
   Какая ветка является production — `master` или `main`?  
   Посмотреть в GitLab: Settings → Repository → Default branch.

2. **Обновить `src/gitlab/config.js`** — добавить строку:
   ```javascript
   { id: <project_id>, targetBranch: 'master' }, // или 'main'
   ```

3. **Обновить таблицы** в этом файле и в [`docs/gitlab-webhooks-setup.md`](./gitlab-webhooks-setup.md) (включая ID в примерах PowerShell).

4. **Создать webhooks** на новый проект — [`docs/gitlab-webhooks-setup.md`](./gitlab-webhooks-setup.md), шаг 3 (только новый ID).

5. **Проверить доступ GitLab token** (`GITLAB_TOKEN` в Railway):
   - Токен должен иметь Developer+ на новом проекте.
   - Для protected branches достаточно прав на **создание MR** (merge не нужен).
   - Проверить: `GET /api/v4/projects/<id>` → должен вернуться объект проекта.

6. **Убедиться в наличии веток** с ключом Jira-задачи (`PROJECT-123`) в новом репо.

7. **Деплой:** смержить PR в основную ветку → Railway автоматически переразвернёт сервис.

## Правила работы бота

- Ищет ветки, в **имени** которых содержится ключ задачи (например, `feature/CPAYMENT-1000`).
- Ветки с подстрокой `from-test` в имени игнорируются при автосоздании MR (например, `CPAYMENT-1642/fix-from-test`).
- Если веток **0** — сообщает в Slack «ветка не найдена».
- Если после исключения `from-test` остаётся **1** ветка — создаёт MR и пишет в Slack, какие ветки были проигнорированы.
- Если после исключения остаётся **≥ 2** веток — сообщает в Slack «несколько веток, нужно разобраться вручную» (MR не создаётся) и при наличии `from-test` упоминает игнорирование.
- Если найдены только ветки с `from-test` — MR не создаётся, в Slack перечисляются проигнорированные ветки.
- Проверяет diff перед созданием MR. Если diff пустой — MR не создаётся.
- Если MR `source → target` уже открыт — не дублирует, даёт ссылку.
- **Конфликты слияния:** после создания MR (или при нахождении уже открытого) бот проверяет `has_conflicts`.
  Если конфликт обнаружен:
  - В Slack добавляется пометка `⚠️ конфликт с \`target\`` и упоминание ответственного.
  - В GitLab MR публикуется комментарий с `@username` и пометкой `[jira-deploy-bot:conflict]`.
  - Повторный комментарий в рамках одного инстанса бота не публикуется (дедупликация по `projectId:mrIid`).
  - Настройка: `GITLAB_MENTION_ON_MR_CONFLICT` (GitLab username, по умолчанию `jbogomolov`),
    `SLACK_MENTION_DEPLOY_CONFLICT` (алиас из `src/slack/members.js`, member ID или `<@U…>`; по умолчанию `jegor`).
